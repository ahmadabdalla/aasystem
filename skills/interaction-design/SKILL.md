# Interaction design

Before starting, read the [shared execution contract](../aapilot/references/execution.md) in full and the [approved-principle index](../principles/INDEX.md). Follow the contract’s baseline requirements.

Own the interaction model for the assigned scope. The caller assigns this responsibility and integrates the result; a standalone request ends with the requested design or review. Product owns intended behavior and business meaning, while architect owns technical implementation design. This skill proposes how people encounter and act on that behavior.

## Ground and design

Read the [interaction contract](references/interaction-contract.md) and follow its phases. Reuse the caller's settled brief, canonical product contract, terminology, decisions, existing experience, and evidence. Scale the deliverable to the decision: a section in an existing document can suffice. Routine presentation changes do not need a complete interaction model or a new approval gate.

Use [arena](../arena/SKILL.md) for consequential unsettled interaction alternatives. Supply the same grounded brief and interaction contract to candidates; preserve its independent comparison and synthesis requirements. Use [prototype](../prototype/SKILL.md) when an inspectable business-state walkthrough, specified presentation or contextual UI comparison can answer the assigned question. For a coupled human review/refinement cycle, return to the caller for a bounded [UI Refinement](../ui-refinement/SKILL.md) assignment. If that caller already owns the refinement cycle, return the model and findings to it without starting another cycle. A sketch is sufficient when it answers the question. These helpers return to this assignment; they do not authorize implementation or establish human acceptance.

Return proposed changes to business meaning, behavior, or scope to [product](../product/SKILL.md) through the caller. Return technical feasibility questions through the caller for a bounded [Architect](../architect/SKILL.md) design/feasibility assignment. Preserve unresolved constraints through both handoffs. Use [solution](../solution/SKILL.md) only when the overall direction needs reconsideration.

## Review and return

Read [review checks](references/review-checks.md) before handing off. Obtain an independent review for a consequential new or revised interaction model when delegation is available and permitted; disclose a lead-only review otherwise. Inspect findings against the artifacts and requirements, integrate supported changes, and recheck the result. Agent agreement cannot replace a required human decision.

Return the interaction model or review findings, canonical decision references, covered and omitted behavior, unresolved choices, evidence and its limits, and the next responsible owner. Follow the contract's recording and verification handoff; do not create a parallel requirement or decision registry.
