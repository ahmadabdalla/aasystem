# Refinement loop

Refine the assigned journey or surface. Reuse sufficient reviewed references or resume the checkpoint without replaying completed phases.

1. **Frame the inspectable slice.** Identify supported behavior, explicit interaction/visual instructions, existing components and what the human needs to inspect. Use conditional grounding for consequential gaps. Start with enough supported behavior for credible inspection; discovery and specifications need not be complete. Preserve plan-only or read-only boundaries.
2. **Render in context.** Use the [rendering assignments](#rendering-assignments) below: Interaction Design receives the grounded scope and [visual-reference contract](../../interaction-design/references/interaction-contract.md#preserve-an-inspectable-visual-reference-when-needed); Prototype receives the proposed experience, constraints and states. Render one candidate unless alternatives discriminate a real choice. Inspect actual navigation and appearance with representative content, relevant viewports and disclosed stubs. Record what was rendered or exercised; markup alone cannot establish visual fidelity. Return missing rendering capability as a gap.
3. **Review and refine.** When the assigned scope calls for independent rendered UX assessment, use [Interaction Design's assessment procedure](../../interaction-design/references/rendered-ux-assessment.md) before the human checkpoint; a producer in this loop cannot fill either assessor seat. Present the rendered experience and a short walkthrough using the shared [human checkpoint handoff](../../aapilot/references/execution.md#decision-authority). Apply the actual answer to owning interaction/presentation records and artifacts; return changed business meaning through the caller to Product. Re-render and inspect changes. Capture supported requirements as they settle. Use existing [decision records](../../domain-modeling/references/adr.md) for acceptance, proposals and supersession without a second status system.
4. **Preserve and return.** Retain the identifiable reviewed source revision, useful rendered views and component/style references through the [interaction contract's handoff](../../interaction-design/references/interaction-contract.md#5-record-and-hand-off). Record accepted scope, explicit constraints, open feedback, unreviewed states/viewports and next action in an existing project record. Return technical-design and verification inputs; prototype operation does not prove production persistence or integration. Reuse sufficient accepted references without another review. The caller resumes authorized delivery; this skill neither routes back into Feature nor repeats implementation planning.

## Rendering assignments

The current owner or one bounded worker may apply [Interaction Design](../../interaction-design/SKILL.md) then [Prototype](../../prototype/SKILL.md) for one coupled candidate when business meaning is settled, artifact ownership and the checkpoint are shared, no required candidate/reviewer independence is merged, and actual host invocation permits both procedures. Choose execution ownership through the [shared delegation rule](../../aapilot/references/execution.md#delegation). Otherwise keep separate scoped assignments or return the unresolved prerequisite or unavailable required handoff to the caller.

Keep roles and scopes, artifact/write ownership, checks, required results and evidence limits in the existing brief or assignment. The executing owner or worker reads both procedures and preserves interaction rationale plus inspected rendered evidence. Role ownership stays intact; required independent reviews and final independent production verification remain separate.
