# Implementation routing evaluation

This package defines planned cases for design-only Architect, standalone Architect design-and-build continuation, assigned and direct Implement entry, independent verification, and correction continuation owned by the caller. Cases remain unexercised until actual run evidence is retained. It follows the [evaluation playbook](../../skills/aapilot/playbooks/eval.md); [criteria](rubric.md) are judge-only. It does not add a generic verifier skill. The fresh verification worker uses the fixture's project-owned `verify-ledger` procedure; optional Interrogate review would be a separate adversarial assessment, not runtime proof.

The fixture is a small standard-library Python CLI with real persisted JSON effects. Its [accepted contract](fixtures/project/README.md), [source](fixtures/project/ledger.py), [smoke tests](fixtures/project/test_cli.py), and [verification recipe](fixtures/project/verify-ledger/SKILL.md) are raw project inputs. The [settled design](fixtures/settled-design.md) belongs only in implementation/coordinator phases. The alternate [verification artifact](fixtures/verification-artifact/ledger.py) belongs only in verification cases and their recorded-failure correction continuation. Candidate requests are selected individually from [requests.md](fixtures/requests.md).

## Phase-scoped materialization

For every row, create a separate fresh project directory by copying the contents of `fixtures/project/`. Supply that candidate its assigned instruction snapshot through the host's supported project-skill mechanism; keep the complete skill tree for shared references. Make the project-owned verifier accessible and explicitly select it if the host requires selection. Record the exact prompt, interpreter/host/model configuration, source hashes, instruction snapshot identity, write ownership, and actual read/access limits. Keep execution evidence outside the source tree. Preserve unsuccessful attempts and label any rerun's reason.

Do not copy this README, rubric, requests for other cases, alternate fixture directories, or unrelated candidate outputs into a candidate project. Only correction continuation receives its prerequisite verifier report. Absolute project paths should point to the materialized copy, not the evaluation package. An instruction snapshot or read-only sandbox does not guarantee read isolation: record any host-exposed parent history, global skills, or other accessible sources. A fresh session by itself is insufficient to establish independent discovery.

Separate the coordinator's stages as well. Its implementation worker receives the accepted design and assignment; its fresh verification worker receives authoritative requirements, the exact changed artifact and access limits, without author conclusions. Return initial verification findings before owner reconciliation. If dispatch fails or threads are unavailable, preserve the denial and keep the relevant gate unverified; a handoff prepared for future execution is not completed verification.

The correction continuation reuses the alternate raw artifact without inserting evaluator annotations or a preferred fix. Dispatch it only after an independent-verification run records the concrete contract violation with reproducible CLI evidence and source identity. Transfer that report as authoritative task input to the owner and correction worker, not as hidden evaluator suspicion. A new materialized copy must match the report's tested product identity. Do not fabricate a verifier report or treat the known fixture defect as observed verification; without the initial report, this continuation remains unexercised.

## Fixture usability and behavioral judgment

From a materialized project, `python3 -m unittest -v` is the smoke command. Both supplied source variants pass it. The verifier's actual CLI recipe should pass the baseline and reject the alternate artifact on observed preview side effects. These fixture self-checks establish usable inputs, not agent behavior.

Run selected requests in fresh candidate contexts only after the assigned instructions stabilize. An independent judge receives the rubric and retained artifacts/traces, inspects actual file scopes and commands, and runs output checks where meaningful. Report design-only execution, implementation, runtime verification, ownership, and independence separately. Include normal execution and at least one boundary case; leave unused cases explicitly unexecuted.

This package defines cases, not a passing evaluation. Explicitly selecting Architect or Implement tests explicit use, not automatic discovery; the multi-skill selections make required continuation capabilities explicit where host policy requires it. A revised-instructions-only run can support bounded compliance observations; improvement needs the prior instructions under comparable conditions. The ordinary coordinated-refactoring case does not force a correction loop; the separate correction continuation supplies an actually recorded failure to exercise that path. Keep every planned case unexercised until its own artifacts and traces establish what ran. Real-project integration and other host support remain separate claims.
