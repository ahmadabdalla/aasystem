# Evaluation

Own the experiment design and the adoption decision. Structural validity, following instructions, and producing correct work are separate claims.

1. **Define success before running.** Name the changed behavior and three to six observable criteria. Keep the scoring rubric with the judge. Include a normal case and a boundary or counterexample that could reveal a bad generalization. When claiming improvement, include the prior version under comparable conditions.
2. **Prepare isolated contexts.** Give each candidate the same realistic task, needed raw artifacts, and its assigned instruction version. Use neutral project and file names. Do not reveal the rubric, suspected defect, preferred fix, other candidates, or which variant should win. A candidate explicitly asked to use a skill tests explicit use; it does not test automatic discovery.
3. **Run independent candidates.** Delegate to fresh contexts where supported and permitted. Use genuinely different models when available and relevant. Assign separate writable locations and confine actions to the exercise. Preserve actual outputs, interactions, failures, and source identities. If fresh contexts are unavailable, record that limitation; an author's walkthrough is not independent behavioral validation.
4. **Judge artifacts and execution.** Use an independent judge with neutrally labeled outputs and the same rubric for all variants. Inspect permitted run records and files actually read to assess routing and handoffs; do not rely on candidate claims about following the skill. Run meaningful output checks where possible. Keep unseen steps unverified. If independent judging is unavailable, label the assessment accordingly.
5. **Reconcile and decide.** The lead reads every result, checks disputed findings, and distinguishes instruction defects, host limits, and fixture faults. Preserve unsuccessful attempts and label reruns with their reason. Avoid broad quality claims from a small sample. Apply only corrections supported by the evidence, then rerun affected cases.
6. **Report the bounded result.** Record prompts, instruction variants, environments, rubric, evidence locations, outcomes, and limitations. State whether the change is supported for the exercised paths and what still needs a real-project or host-specific check.
