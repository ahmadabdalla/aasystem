# Bug fix

Own reproduction, causal diagnosis, correction, and proof. Every retained production change must address the demonstrated mechanism. Discard experimental changes whose hypothesis was refuted, preserving unrelated work.

1. **Reproduce on the affected surface.** Follow the [execution contract](../references/execution.md) to find or establish the project verifier. Record intended behavior, the triggering action, actual failure, environment, and source identity before changing product code. Drive the relevant surface yourself. If direct reproduction fails, tighten conditions, synthesize a representative trigger, or instrument it. A surrogate narrows the claim; it does not establish that the reported failure was reproduced. Ask the user to perform an unreachable action only after recording the specific access or control limit and what you tried. If asking, stop and wait.
2. **Eliminate causal hypotheses.** Use [how](../../how/SKILL.md) for the path and [why](../../why/SKILL.md) for regression history. Choose observations that separate the remaining explanations; use [probe](../../probe/SKILL.md) and runtime instrumentation when state is unclear. Confirm the surviving mechanism with runtime evidence before design or implementation. If evidence remains insufficient, return an unresolved diagnosis with the next discriminating observation; do not ship a speculative fix as confirmed.
3. **Plan and implement the correction.** When the correction meets the [Architect design trigger](../../architect/SKILL.md#design-trigger), use Architect with a design-only assignment and the confirmed mechanism. For a cheap local regression path or an explicit testing request, use [tdd](../../tdd/SKILL.md) before the product edit. Agree the test owner so the failing check is executed before implementation starts. Delegate the bounded fix where permitted, preserve nearby contracts, and review the actual diff. Remove investigation-only changes unless they have an independently justified purpose.
4. **Replay the original failure.** Exercise the same surface, trigger, and relevant conditions on the corrected artifact. Check the original result and side effects, the regression test where present, and affected neighboring paths. Wrong-surface or inconclusive evidence is not a pass. A unit test establishes its tested behavior, not absence of the reported integration bug.
5. **Preserve the proof and deliver.** Retain failing-before and passing-after evidence. When commits are in scope, place an executable reproduction before the fix where practical and consistent with project rules. Follow the execution contract for delivery; use [Opening a PR](opening-a-pr.md) when authorized.

Report what failed, its confirmed cause or remaining uncertainty, the correction, and the exact observed outcomes. Include concise failing/passing output or links to the relevant evidence, without secrets.
