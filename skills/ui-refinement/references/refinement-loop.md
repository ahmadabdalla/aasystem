# Refinement loop

Refine the assigned journey or surface. Reuse sufficient reviewed references or resume the checkpoint without replaying completed phases.

1. **Frame the inspectable slice.** Identify supported behavior, explicit interaction/visual instructions, existing components and what the human needs to inspect. Use conditional grounding for consequential gaps. Start with enough supported behavior for credible inspection; discovery and specifications need not be complete. Preserve plan-only or read-only boundaries.
2. **Render in context.** Give Interaction Design the grounded scope and [visual-reference contract](../../interaction-design/references/interaction-contract.md#preserve-an-inspectable-visual-reference-when-needed), then Prototype the proposed experience, constraints and states. Render one candidate unless alternatives discriminate a real choice. Inspect actual navigation and appearance with representative content, relevant viewports and disclosed stubs. Record what was rendered or exercised; markup alone cannot establish visual fidelity. Return missing rendering capability as a gap.
3. **Review and refine.** Present the rendered experience and a short walkthrough. At human review checkpoints, ask for focused feedback and stop. Apply the answer to owning interaction/presentation records and artifacts; return changed business meaning through the caller to Product. Re-render and inspect changes. Capture supported requirements as they settle. Use existing [decision authority](../../domain-modeling/references/adr.md) for acceptance, proposals and supersession without a second status system.
4. **Preserve and return.** Retain the identifiable reviewed source revision, useful rendered views and component/style references through the [interaction contract's handoff](../../interaction-design/references/interaction-contract.md#5-record-and-hand-off). Record accepted scope, explicit constraints, open feedback, unreviewed states/viewports and next action in an existing project record. Return technical-design and verification inputs; prototype operation does not prove production persistence or integration. Reuse sufficient accepted references without another review. The caller resumes authorized delivery; this skill neither routes back into Feature nor repeats implementation planning.
